# Papito

Демонстрационный сайт ресторана: меню, корзина, оформление и отслеживание заказа.

## Стек и запуск

Next.js 16.4.0 (App Router), React 19.3.0, TypeScript, Tailwind CSS 4, npm.
Используйте Node.js **24.x** — версия указана в `package.json` и `.nvmrc`.

```powershell
npm ci
npm run dev
```

Откройте адрес, выведенный в терминале (обычно http://localhost:3000).

Перед публикацией:

```powershell
npm test
npm run lint
npm run build
npm start
```

`npm ci` использует зафиксированные зависимости из `package-lock.json`. Этот файл нужно хранить в Git.
Сборка загружает шрифт Manrope через `next/font/google`; машине сборки нужен доступ к Google Fonts.

## Что именно будет опубликовано

- `/` — меню с тремя тестовыми позициями и корзиной.
- `/order/[id]` — отслеживание заказа из текущего браузера.
- `/admin` — управление локальным меню; `/kitchen` — демонстрационная кухня.
- Меню, корзина и заказы сохраняются в **localStorage**, а не в общей базе данных. Синхронизация работает только между вкладками одного браузера на одном домене.
- Заказы не отправляются в ресторан, платежи не проводятся. Служебные страницы не имеют авторизации и доступны по прямому URL, но изменяют только локальные данные посетителя.
- При переходе с localhost на домен Vercel, между preview-доменами или на собственный домен локальные данные не переносятся.
- Тестовые позиции помечены `isTest: true` в `src/data/testProducts.ts`. Изменения стартовых данных не перезаписывают уже сохранённое меню; его можно редактировать через `/admin`.

Это готовность к публикации **демоверсии**, не к приёму реальных заказов. Серверную обработку, авторизацию и оплату этот этап не добавляет.

## Публикация через GitHub

Локальный репозиторий уже инициализирован, ветка — `main`. Коммитов и удалённого репозитория пока нет.

1. Войдите в GitHub и создайте **пустой** репозиторий `papito`. Не добавляйте README, лицензию или `.gitignore` на GitHub: они создадут отдельную историю. Можно выбрать Private — Vercel умеет подключать приватные репозитории.
2. В PowerShell откройте папку проекта:

   ```powershell
   cd C:\Users\lmm\Documents\Papito
   git status --short
   git add .
   git diff --cached --stat
   git diff --cached --name-only
   ```

3. Проверьте список перед коммитом. В нём должны быть исходники, фотографии, тесты, конфигурация и `package-lock.json`. **Не должно быть** `.env*`, `.npmrc`, приватных ключей, `.vercel`, `node_modules` или `.next`. Эти пути исключены в `.gitignore`; не используйте `git add -f` для их добавления.
4. Создайте коммит:

   ```powershell
   git commit -m "Prepare Papito demo for Vercel"
   ```

   Если Git запросит имя и email, настройте их локально командами `git config user.name "Ваше имя"` и `git config user.email "Ваш email GitHub"`, затем повторите коммит. Можно использовать noreply-email из настроек GitHub.

5. Подставьте свой GitHub-логин вместо `YOUR_USERNAME`:

   ```powershell
   git remote add origin https://github.com/YOUR_USERNAME/papito.git
   git push -u origin main
   ```

   Авторизуйтесь через Git Credential Manager/браузер при запросе. Не вставляйте токен в URL репозитория, исходники или команды, которые сохраняются в истории.

## Публикация на Vercel

1. Войдите в Vercel и выберите **Add New → Project**.
2. Подключите GitHub и разрешите доступ к репозиторию `papito`, затем нажмите **Import**.
3. Проверьте настройки:

   | Параметр | Значение |
   | --- | --- |
   | Framework Preset | Next.js |
   | Root Directory | `./` — папка с `package.json` |
   | Node.js Version | `24.x` |
   | Install Command | `npm ci` |
   | Build Command | `npm run build` |
   | Output Directory | Оставить стандартное значение Next.js, без Override |
   | Environment Variables | Для текущей демоверсии не нужны |

   `next.config.ts` уже содержит обработчик Tailwind для Turbopack. Он установлен в зависимостях; не заменяйте команду сборки на webpack. `vercel.json`, статический экспорт и перенаправление всех адресов на `/` не требуются.

4. Нажмите **Deploy**, дождитесь статуса **Ready** и откройте выданный HTTPS-адрес.
5. Проверьте меню и все три фотографии. Добавьте по одной позиции: сумма корзины должна быть **977 ₽**; с двумя бургерами — **1 326 ₽**. Убедитесь, что количество можно уменьшать и позиции удаляются. При оформлении учитывайте существующую скидку на первый заказ: итог оформления может отличаться от суммы корзины.
6. Создайте демонстрационный заказ и откройте `/kitchen` **в том же браузере и на том же домене**. Проверьте обновление статуса. Не вводите реальные платёжные данные.
7. При необходимости подключите собственный домен в настройках проекта Vercel → Domains и внесите предложенные Vercel DNS-записи у регистратора.

После подключения новые коммиты в production-ветку `main` запускают повторный деплой. Проверьте назначение production-ветки в настройках проекта.

## Проверка на телефоне перед передачей пользователям

Проверки подготовки (2026-10-11): в отдельной чистой копии прошли `npm ci`, все 4 теста, ESLint, TypeScript и production-сборка. Собранное приложение запущено через `npm start`: главная, служебные страницы, маршрут заказа и три фотографии отвечают HTTP 200; неизвестный маршрут — 404. В HTML присутствует мобильный viewport. Проверка выполнялась на Windows с Node.js 24; сборка в инфраструктуре Vercel будет проверена при первом Deploy.

Проверены адаптивные классы меню, шапки, корзины и оформления. В строке корзины разрешён перенос количества и цены на узких экранах. Визуальные браузерные тесты в среде подготовки не выполнены: запуск браузера ранее заблокирован автоматической проверкой безопасности.

Вручную проверьте опубликованный сайт в Safari на iPhone и Chrome на Android, а также при ширинах 320, 375, 390 и 768 px в DevTools:

- Меню видно сразу; нет горизонтальной прокрутки страницы.
- Карточки, цены и кнопки не перекрываются, все фотографии загрузились.
- Корзина открывается и закрывается, итог пересчитывается, после перезагрузки состав сохраняется.
- Оформление прокручивается; при открытой клавиатуре доступны поля и кнопка подтверждения.
- Ошибки пустых полей видны; доставка показывает адрес; успешное оформление открывает статус заказа.
- При повороте телефона содержимое остаётся доступным.

## Секреты

В проекте не требуются токены или `.env`. Проверка известных форматов секретов не нашла совпадений, но не заменяет просмотр подготовленного коммита. `.gitignore` исключает `.env*`, `.npmrc`, `.vercel` и файлы приватных ключей.

Если секреты понадобятся позже, храните их в Environment Variables проекта Vercel, отдельно для Production и Preview. Не используйте префикс `NEXT_PUBLIC_` для секретов: такие значения доступны браузеру. В `public/` должны находиться только общедоступные файлы.
